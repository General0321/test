# XProbe - Burp Suite 被动安全扫描器

> 基于配对架构的智能漏洞检测插件，支持多阶段链式检测、跨配对变量传递和自动参数发现

## 📌 简介

XProbe 是一款专为 Burp Suite 设计的被动安全扫描器，采用创新的**配对架构（Pair-based Architecture）**，能够检测复杂的多阶段漏洞，如 IDOR、CSRF Token 绕过、时间盲注、布尔盲注等。

### 为什么选择 XProbe？

- 🎯 **配对架构**：灵活组合多个请求-响应配对，构建复杂检测流程
- 🔗 **变量传递**：自动提取和传递变量，支持多阶段漏洞检测
- 🤖 **智能参数发现**：集成 Java 原生 Arjun，自动发现隐藏参数
- ⚡ **高性能**：LRU 缓存、智能去重、线程池优化
- 🎨 **易用界面**：直观的图形界面，无需编写代码

## 🚀 快速开始

### 安装

1. **构建项目**
   ```bash
   ./gradlew build
   ```

2. **加载插件**
   - 打开 Burp Suite Professional
   - Extensions → Add → Extension type: **Java**
   - Select file: `build/libs/XProbe-1.0.0.jar`

3. **开始使用**
   - 插件加载后，Burp Suite 顶部会出现 **XProbe** 标签页
   - 点击进入，开始配置扫描规则

### 第一个扫描规则

1. 进入 **🔍 被动扫描规则** 标签页
2. 点击 **添加规则** 按钮
3. 选择 **简单模式**（单配对）
4. 配置请求匹配条件和响应匹配条件
5. 保存并启用规则

## 💡 核心概念

### 配对（Pair）

一个**配对**包含：
- **请求配置**：定义哪些请求需要检测（匹配条件）和如何修改请求（注入点）
- **响应配置**：定义如何判断响应是否匹配（匹配条件）

### 简单模式 vs 高级模式

**简单模式**：单个配对，适合简单漏洞检测
```
请求匹配 → 注入Payload → 响应匹配 → 结果
```

**高级模式**：多个配对 + 逻辑表达式，适合复杂漏洞检测
```
Pair 1: 创建订单 → 提取 order_id
Pair 2: 使用 order_id 访问订单
表达式: 1 AND 2  (两个配对都成功才算漏洞)
```

### 变量传递

**场景**：检测 IDOR 漏洞

1. **Pair 1**：创建订单，从响应中提取 `order_id`
   ```
   响应: {"order_id": "12345", ...}
   提取规则: {"order_id": "\"order_id\":\"(\\d+)\""}
   ```

2. **Pair 2**：使用提取的 `order_id` 访问订单
   ```
   请求: GET /api/order/{{PAIR:1:order_id}}
   实际请求: GET /api/order/12345
   ```

## 🎯 典型使用场景

### 场景1：SQL 注入检测

**配置：**
- 请求匹配：URL 包含 `/api/query`
- 注入点：参数 `id`
- Payload：`' OR '1'='1`
- 响应匹配：响应体包含 `SQL syntax`

### 场景2：IDOR 漏洞检测

**Pair 1 - 创建资源：**
- 请求：`POST /api/order`，Body: `{"product_id": 123}`
- 响应匹配：状态码 200
- 变量提取：`{"order_id": "\"order_id\":\"(\\d+)\""}`

**Pair 2 - 访问资源：**
- 请求：`GET /api/order/{{PAIR:1:order_id}}`
- 响应匹配：状态码 200

**配对表达式：** `1 AND 2`

### 场景3：时间盲注检测

**Pair 1 - 基线请求：**
- 请求：`GET /api/user?id=1`
- 用途：记录正常响应时间

**Pair 2 - 时间延迟注入：**
- 请求：`GET /api/user?id=1' AND SLEEP(5)--`
- 响应对比：
  - 时间对比模式：**相对配对**
  - 引用配对：**1**
  - 倍数：**3.0**（响应时间应该是 Pair 1 的 3 倍）

**配对表达式：** `1 AND 2`

### 场景4：CSRF Token 绕过

**Pair 1 - 获取 Token：**
- 请求：`GET /api/form`
- 变量提取：`{"csrf_token": "name=\"csrf_token\" value=\"([^\"]+)\""}`

**Pair 2 - 使用 Token 提交：**
- 请求：`POST /api/submit`
- Body：`csrf_token={{PAIR:1:csrf_token}}&data=test`

## 📚 功能详解

### 1. 请求配置

**匹配条件**：定义哪些请求需要检测
- HTTP 方法（GET、POST 等）
- URL 路径
- 请求参数
- 请求头
- Cookie
- 请求体

**注入点**：定义如何修改请求
- 参数值注入
- 请求头注入
- Cookie 注入
- URL 路径注入
- 请求体注入

**Payload 变量**：
- `{{ORIGINAL}}` - 原始值
- `{{RANDOM_STRING}}` - 随机字符串
- `{{COLLABORATOR}}` - Burp Collaborator 域名
- `{{UUID}}` - UUID
- `{{TIMESTAMP}}` - 时间戳
- `{{BASE64:xxx}}` - Base64 编码
- `{{URL_ENCODE:xxx}}` - URL 编码

### 2. 响应配置

**匹配条件**：
- 状态码
- 响应头
- 响应体（字符串匹配、正则匹配）
- 响应时间
- 响应长度
- Collaborator 交互

**变量使用**：
- `{{VAR:name}}` - 从任意配对获取变量
- `{{PAIR:id:name}}` - 从指定配对获取变量

### 3. 跨配对配置

**响应对比**：
- 状态码对比
- 长度对比
- 时间对比（绝对/相对基线/相对配对）
- 响应体对比（相等/不等/相似/不相似）

**变量提取**：
- 使用正则表达式从响应中提取数据
- 提取的变量自动注册为多种格式
- 可在后续配对中使用

### 4. 参数发现（Arjun）

**功能**：
- 自动发现隐藏参数
- 实时参数收集
- 智能触发扫描

**配置**：
- 参数数量阈值：达到阈值时自动触发
- 扫描间隔：防止频繁扫描
- 线程数：并发扫描线程数

## ⚙️ 配置说明

### 全局配置

在 **⚙️ 配置中心** 标签页中配置：

- **黑白名单**：设置请求过滤规则
- **Arjun 配置**：参数发现相关配置
- **参数收集模式**：仅参数名 / 参数名+关键词
- **线程池配置**：扫描任务线程池参数
- **日志模式**：日志记录模式

### 扫描规则配置

在 **🔍 被动扫描规则** 标签页中：

1. **添加规则**：点击"添加规则"按钮
2. **选择模式**：简单模式（单配对）或高级模式（多配对）
3. **配置配对**：
   - 请求配置：匹配条件和注入点
   - 响应配置：匹配条件
   - 跨配对配置：响应对比和变量提取（高级模式）
4. **配对表达式**：多配对时配置逻辑表达式（如：`1 AND 2 OR 3`）
5. **保存规则**：保存并启用规则

### 去重配置

支持多种去重颗粒度：
- **AUTO**：自动检测（推荐）
- **URL**：仅按 URL 去重
- **PARAMETER**：按 URL + 参数名去重
- **PARAMETER_VALUE**：按 URL + 参数名 + 参数值去重

## 🔧 高级功能

### 批量模式 vs 逐个模式

**批量模式**：所有匹配的参数同时注入相同的 Payload
- 优点：速度快，适合测试多个参数
- 缺点：无法区分是哪个参数触发的漏洞

**逐个模式**：每个参数分别注入 Payload
- 优点：可以精确定位触发漏洞的参数
- 缺点：速度较慢

### 被动检测 vs 主动注入

**被动检测**：不修改请求，直接使用原始响应进行匹配
- 适用场景：检测响应中的敏感信息泄露、默认配置等

**主动注入**：修改请求，注入 Payload，分析响应
- 适用场景：SQL 注入、XSS、命令注入等需要注入 Payload 的漏洞

### 变量提取规则

**格式**：`{"变量名": "正则表达式"}`

**要求**：
- 正则表达式必须包含**捕获组**（括号）
- 提取的是第一个捕获组的值

**示例**：
```json
{
  "order_id": "\"order_id\":\"(\\d+)\"",
  "csrf_token": "name=\"csrf_token\" value=\"([^\"]+)\"",
  "user_id": "id=(\\d+)"
}
```

## 📖 最佳实践

1. **合理使用去重**：根据场景选择合适的去重颗粒度，避免重复扫描
2. **优化 Payload**：使用变量减少重复配置，提高可维护性
3. **利用变量传递**：多阶段漏洞检测时，充分利用变量传递功能
4. **配置响应对比**：时间盲注、布尔盲注等场景，使用响应对比功能
5. **定期清理缓存**：长时间运行后，定期清理缓存以释放内存

## 🐛 常见问题

**Q: 为什么扫描结果中没有显示漏洞？**
A: 检查以下几点：
- 规则是否已启用
- 请求是否匹配规则的条件
- 响应是否匹配规则的匹配条件
- 查看日志了解详细信息

**Q: 如何提取 JSON 响应中的变量？**
A: 使用正则表达式，例如：
```json
{"user_id": "\"id\":(\\d+)"}
```

**Q: 变量提取失败怎么办？**
A: 检查：
- 正则表达式是否正确（必须包含捕获组）
- 响应中是否真的包含要提取的内容
- 查看日志了解详细错误信息

**Q: 如何检测时间盲注？**
A: 使用高级模式：
- Pair 1：基线请求（正常请求）
- Pair 2：注入时间延迟 Payload
- 配置响应对比：时间对比模式选择"相对配对"，引用 Pair 1
